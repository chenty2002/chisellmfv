Round 2: Fixed uninitialized RegNext registers causing load_mode_update and spin_mode_update assertion failures. Error type: dut_bug. Root cause: `dinDelayed = RegNext(io.din)` and `doutRegDelayed = RegNext(doutReg)` lacked explicit reset values, allowing the formal solver to pick arbitrary initial values (e.g., 0x80000000 for dinDelayed) that mismatch the properly-reset inrReg (0x00000000) at cycle 0. The fix adds `0.U(32.W)` as reset value to both RegNext calls on lines ~98 and ~94: `RegNext(io.din, 0.U(32.W))` and `RegNext(doutReg, 0.U(32.W))`. This ensures that after reset all registers (inrReg, dinDelayed, doutRegDelayed) agree on value 0, so the load_mode_update and spin_mode_update assertions hold at cycle 0 and thereafter. All three assertion labels (rotation_correctness, spin_mode_update, load_mode_update) are preserved unchanged.
