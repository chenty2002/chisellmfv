Round 1/3: Fixed DUT timing bug where position overshoots the required value in the same cycle a state transition fires. Root cause: position update and state machine transition are both registered and update simultaneously — when position=12 triggers state 0→1, position increments to 13 in the same cycle, causing assertion entry_state1_requires_pos12_up to fail. Fix adds `freezePosition` signal that prevents position from incrementing/decrementing when any entry-transition condition is about to fire (state=0 & pos=12 & upReg, state=1 & pos=21 & downReg, state=2 & pos=15 & upReg). This is a homologous repair: all three structurally identical entry assertions (entry_state1_requires_pos12_up, entry_state2_requires_pos21_down, entry_state3_requires_pos15_up) are fixed by the same mechanism. The exit assertions and liveness property are also expected to benefit because position no longer overshoots during transitions, preserving the intended temporal semantics.
