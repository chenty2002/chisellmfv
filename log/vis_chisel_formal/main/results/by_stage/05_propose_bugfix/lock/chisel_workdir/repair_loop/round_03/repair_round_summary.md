Round 3/3: Two fixes applied. (1) DUT bug: removed `when(upReg) { state := 0.U }` in state 1 and `when(downReg) { state := 0.U }` in state 2 — these resets made it structurally impossible to ever reach state 2 or 3 because pressing UP (needed to advance position toward 21) or DOWN (needed to advance position toward 15) immediately reset the state machine to 0. Fix preserves state 3→0 reset on any press. (2) Assertion bug: fixed `position_stable_when_both_pressed` — the old check `position === prevPosition` (where prevPosition=RegNext(position)) falsely failed when position was updated in the previous cycle (single-button press) then both-buttons-pressed in the current cycle, because prevPosition held the stale value from 2 cycles ago. New check directly asserts that neither update condition fires when both buttons are pressed, which is correct by construction of the position update logic. All assertion labels preserved.
