Repair round 1/3: Fixed all 8 failing `assertNextStepWhen` assertions by replacing them with explicit `RegNext`-based implication assertions. Root cause: `assertNextStepWhen` wraps `fvAssert` inside a `when` block, which the Chisel→Verilog compiler drops, producing unconditional SVA assertions that fire every cycle. Fix: each `assertNextStepWhen(ant, cons, name)` → `{ val antPrev = RegNext(ant, false.B); fvAssert(!antPrev || cons, name) }`. This creates a one-cycle-delayed sample of the antecedent and uses a combinational implication expression (`!antPrev || cons`) inside `fvAssert`, which the compiler correctly preserves. All 8 assertion labels preserved: state_E_is_sink, A_stays_on_input_0, A_goes_to_B_on_input_1, B_goes_to_D_on_input_0, B_goes_to_C_on_input_1, C_goes_to_B, D_goes_to_E, E_stays_in_E.
