## 2. Violated Assertion

### Full Assertion Name
`b02.U_reg_should_assert_within_8_cycles_after_reset`

### Code Snippet (b02.scala, lines 101–113)
```scala
  // Bounded liveness: After reset, the FSM should assert U=1 within a bounded
  // number of cycles. The longest non-looping path from reset (StateA) to StateE
  // is 4 cycles (A->B->C->D->E or A->B->F->G->E).  We use a relaxed bound of 8
  // to cover cases where LINEA causes short loops before reaching StateE.
  // Fairness constraint: LINEA must go low periodically to prevent infinite
  // loops through A->B->F->G->A when LINEA is stuck high.
  val lineaHighCycles = RegInit(0.U(3.W))
  when(io.LINEA) {
    lineaHighCycles := lineaHighCycles + 1.U
  }.otherwise {
    lineaHighCycles := 0.U
  }
  assume(lineaHighCycles < 6.U, "LINEA fairness: must go low every 6 cycles")
  astRelaxedLiveness(!reset.asBool, U_reg, 8, "U_reg should assert within 8 cycles after reset")
```

### Property Description
The assertion states: **After reset is deasserted, the output `U_reg` must become true within 8 clock cycles.** The bound of 8 was chosen to account for short loops caused by LINEA timing, with a fairness assumption that LINEA goes low at least once every 6 consecutive cycles.

## 4. Root Cause Analysis

### Classification: **Assertion Error** (Bound too tight)

### Buggy Element
The **assertion bound of 8 cycles** (line 113 of `b02.scala`) is insufficient to guarantee that `U_reg` becomes true under all valid input sequences allowed by the fairness constraint `assume(lineaHighCycles < 6.U)`.

### Root Cause Description

The FSM requires one of two specific paths to reach **StateE** where `U_reg=1`:

| Path | Sequence | Necessary LINEA values |
|------|----------|----------------------|
| **Path 1** (short): 4 cycles | A→B→**F**→**G**→**E** | LINEA=1 at B, **LINEA=0 at G** |
| **Path 2** (short): 4 cycles | A→B→**C**→**D**→**E** | LINEA=0 at B, **LINEA=0 at C** |

Both paths require LINEA=0 at a **specific critical state** (StateC for Path 2, or StateG for Path 1). However, the fairness constraint `lineaHighCycles < 6` only guarantees that LINEA goes low *at least once every 6 cycles* — **it does not guarantee LINEA is low at the right state**.

### Waveform Evidence

In the counterexample, the FSM enters **two unproductive loops** that never reach StateE:

**Loop 1** (cycles 1–4): `A → B → C → G → A`
- At **StateB** (t=10): LINEA=0 → takes Path 2 toward D/E ✓
- At **StateC** (t=20): LINEA=1 → goes to G instead of D **✗**
- At **StateG** (t=30): LINEA=1 → goes back to A instead of E **✗**
- Result: **4 cycles wasted**, returns to A without asserting U_reg

**Loop 2** (cycles 5–8): `A → B → F → G → A`
- At **StateB** (t=50): LINEA=1 → takes Path 1 toward E ✓
- At **StateF** (t=60): unconditional → G ✓
- At **StateG** (t=70): LINEA=1 → goes back to A instead of E **✗**
- Result: **4 more cycles wasted**, returns to A without asserting U_reg

### Why the Bound Fails

At t=90 (cycle 9), the timer reaches 8 and the assertion fires. The FSM is at StateB, still 3 states away from StateE even under the best case. **The bound of 8 does not provide enough margin** for scenarios where LINEA transitions happen at inopportune times relative to the FSM state.

Specifically:
1. LINEA goes low for **one cycle** at t=60 (at StateF, not at StateG where it matters)
2. The fairness constraint allows this — LINEA was high for 4 consecutive cycles (t=20–50, `lineaHighCycles`=1→4), well within the <6 limit
3. LINEA goes high again at t=70 (when the FSM is at StateG), blocking the only opportunity to reach StateE
4. By t=90, the timer has expired without U_reg ever being asserted

### Recommended Fix

**Option A (Recommended — Increase the bound):** Increase the bound from 8 to a larger value (e.g., 12–16) to provide sufficient margin for worst-case LINEA timing sequences that still satisfy the fairness constraint.

**Option B (Strengthen the fairness constraint):** Add an additional fairness constraint requiring LINEA=0 at specific critical junctures, or require LINEA to stay low for multiple consecutive cycles when it does go low.

**Option C (Investigate DUT):** Root cause is NOT a DUT bug — the FSM implements the ITC99 b02 specification correctly. The issue is that the formal bound under-approximates the worst-case cycles needed to reach StateE given the weak fairness constraint.
