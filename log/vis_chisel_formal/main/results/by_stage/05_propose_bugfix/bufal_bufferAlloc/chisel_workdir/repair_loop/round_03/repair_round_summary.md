Repair round 3/3: Fixed assertion `alloc_progress` (astRelaxedLiveness). Error category: assertion_error. Root cause: the consequent `io.nack || count_increased || !alloc` fails when alloc stays permanently high and simultaneous free keeps count unchanged (one buffer freed, another allocated each cycle). Although the DUT correctly services every allocation, the assertion could not detect progress because `io.nack` is false (count<16), `count_increased` is false (count unchanged), and `!alloc` is false (alloc stays high). Fix: added `val alloc_serviced = RegNext(alloc && !io.nack)` and included it in the consequent as `alloc_serviced`. This temporal-sampling register snapshots the combinational `alloc && !io.nack` value (allocation in progress) from the previous cycle, detecting that allocation IS being serviced even when count doesn't increase. This directly addresses the causal path: the assertion was blind to the steady-state alloc+free scenario where every alloc request is serviced but net allocation is zero. The assertion label `alloc_progress` is preserved unchanged. No homologous assertions — only one astRelaxedLiveness call in the file.
