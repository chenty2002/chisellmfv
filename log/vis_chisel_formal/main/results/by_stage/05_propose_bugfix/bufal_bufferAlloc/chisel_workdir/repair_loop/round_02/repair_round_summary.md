Repair round 2/2: Fixed assertion `alloc_progress` (astRelaxedLiveness). Error category: assertion_error. Root cause: the consequent `io.nack || count_increased` fails when simultaneous alloc+free occurs (count stays unchanged because one buffer is freed while another is allocated). The DUT correctly services the request (alloc goes low next cycle) but the assertion's progress condition was too narrow. Fix: added `!alloc` to the consequent, yielding `io.nack || count_increased || !alloc`. This recognizes that when the alloc request deasserts (the registered alloc goes low), the allocation has been serviced — capturing progress from simultaneous alloc+free scenarios. The assertion label `alloc_progress` is preserved unchanged. No homologous assertions — only one astRelaxedLiveness call in the file.
