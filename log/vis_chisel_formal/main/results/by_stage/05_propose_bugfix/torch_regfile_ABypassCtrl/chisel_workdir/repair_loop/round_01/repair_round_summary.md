Repair round 1/3: Fixed 4 assertStableWhen assertions (AValid_s2e_stable_during_stall, BValid_s2e_stable_during_stall, ABoosted_s2e_stable_during_stall, BBoosted_s2e_stable_during_stall) using a 2-cycle stability check. The root cause was a false-positive on the first stall cycle: the assertStableWhen macro's reference register 'r' captures the pre-update value of the pipeline signal at posedge, while the signal itself is legitimately updated in the same (non-stalled) cycle. When stall first goes high in the next cycle, r still holds the stale pre-update value, causing a spurious assertion failure. Fix replaces assertStableWhen with fvAssert using a RegNext-delayed stall qualifier (stall_s1_d1) so the stability check only fires when stall has been high for >=2 consecutive cycles. All 4 assertion labels preserved identically.
