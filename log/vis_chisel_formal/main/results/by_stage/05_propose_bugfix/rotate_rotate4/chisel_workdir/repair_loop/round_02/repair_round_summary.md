Round 2/3 (fix 2): Fixed `inputsStable` computation for assertion `output_stable_when_inputs_stable`. Root cause: `io.din === RegNext(io.din)` always evaluates to true in formal verification because RegNext captures the same clock-edge value, making the stability detection useless and causing spurious assertion failures when inputs change. Changed to `dinPrev === RegNext(dinPrev) && amountPrev === RegNext(amountPrev)` where `dinPrev`/`amountPrev` are RegNext of inputs — comparing two consecutive registered values correctly detects actual input changes. The original assertion label `output_stable_when_inputs_stable` is preserved exactly.
