# Counterexample Analysis Report

## 1. Verification Environment

- **Top Module**: `field5` (Chisel module)
- **Generated Verilog**: `field5` compiled from `field5.scala`
- **Key Components**:
  - `board` — A `RegInit(Vec(25, UInt(1.W)))` representing a 25-hole peg solitaire board (5×5 grid)
  - `nextBoard` — A combinational `Wire(Vec(25, UInt(1.W)))` used to compute the next board state
  - `io.from` — Input: selected hole position (5-bit)
  - `io.dir` — Input: direction (U/D/L/R, 2-bit)
  - `io.cnt` — Output: number of pegs on the board
  - `resetCounter` — Internal reset sequencing logic (generated by `chiselFv` formal framework)
- **Description**: A peg solitaire puzzle. Initially, pegs are placed in 23 holes, with the center hole (position 12) and lower-right corner (position 24) left empty. Each move jumps one peg over an adjacent peg into an empty hole, removing the jumped peg.

## 2. Violated Assertion

- **Assertion Name**: `center_empty`
- **Waveform Filename**: `field5.center_empty.fst`
- **Code Snippet** (from `field5.scala`, lines 120-121):
  ```scala
  // Safety 2: Center hole (position 12) is always empty
  fvAssert(board(12) === 0.U, "center_empty")
  ```
- **Property Description**: The center hole (board index 12, i.e. the 13th hole in the 5×5 grid) must always be empty (value `0`). This is a safety invariant of the peg solitaire puzzle — the center starts empty and should remain empty.
- **File Location**: `field5.scala`, line 121

## 4. Root Cause Analysis

### Buggy Code Location

- **File**: `field5.scala`
- **Lines**: 65-67
- **Module**: `field5`
- **Bug Type**: **Bug in the Original Design (DUT Bug)**

### Description of the Bug

The board register is initialized and then immediately overridden:

```scala
// Line 64:
val board = RegInit(VecInit(Seq.fill(25)(1.U(1.W))))

// Lines 66-67: These assignments are supposed to make holes 12 and 24 empty
board(12) := 0.U
board(24) := 0.U

// ...
// Line 89:
val nextBoard = Wire(Vec(25, UInt(1.W)))
nextBoard := board    // <- Copies board (still all-1s at this point, since board(12):=0.U and board(24):=0.U are overridden)

// ...
// Line 107:
board := nextBoard    // <- Overwrites everything including the individual element assignments above
```

**The problem**: In Chisel, the `:=` operator for element-wise connections (`board(12) := 0.U`) competes with the whole-vector connection (`board := nextBoard`). Since `board := nextBoard` appears **after** the element-wise assignments in the module body, it wins the connection priority — the individual `board(12) := 0.U` and `board(24) := 0.U` connections are effectively dead code, overridden by the bulk assignment.

Furthermore, `nextBoard := board` copies the register's initial state (all 1s, from `RegInit`), so `nextBoard` is all 1s before any move is executed. When `board := nextBoard` fires, the board remains all 1s, defeating the intended initialization of holes 12 and 24 to 0.

### Evidence from Waveform

1. At t=0 ns, `field5.board_12 = 1` (value is 1, not 0 as intended by `board(12) := 0.U`)
2. At t=0 ns, `field5.board_24 = 1` (value is 1, not 0 as intended by `board(24) := 0.U`)
3. All 25 board positions are 1 at all time points (t=0, t=5, t=10)
4. `io_cnt` = 1 (decimal), i.e. all 25 positions are 1 → count = 25, not 23 as the puzzle specification requires
5. Reset signals are both 0 throughout, so the board is not being held in reset

### Why This Causes the Assertion to Fail

The assertion `fvAssert(board(12) === 0.U, "center_empty")` expects the center hole to be empty (0). Since the initialization to 0 is overridden by `board := nextBoard`, the center hole retains its `RegInit` value of 1. The assertion fails on every cycle, including the very first one.

### Suggested Fix

Replace the separate `RegInit` + element assignments with a properly initialized vector:

```scala
// Before (buggy):
val board = RegInit(VecInit(Seq.fill(25)(1.U(1.W))))
board(12) := 0.U
board(24) := 0.U

// After (fixed):
val initValues = Seq.fill(25)(1.U(1.W))
initValues(12) = 0.U(1.W)
initValues(24) = 0.U(1.W)
val board = RegInit(VecInit(initValues))
```

This ensures that holes 12 and 24 are initialized to 0 inside the `RegInit`, so they cannot be overridden by subsequent whole-vector assignments.
