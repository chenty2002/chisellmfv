Repair round 1/1: DUT bug fix in newHanoi.scala. Root cause: the `legal` signal (line 39) did not validate that `io.from` and `io.to` are valid peg values (0, 1, or 2). When `io.to=3` (invalid), the design treated it as an empty peg and allowed the move, causing disc corruption to invalid peg value 3, triggering all `disc_*_valid_peg` and `disc_*_stable_when_illegal` assertions. Fix: added `validPegs = io.from <= 2.U && io.to <= 2.U` guard to the `legal` signal on line 39, preventing any move with invalid peg inputs. This addresses the causal path: without this guard, the priority encoder for `toMatches` sees no matches (since no disc is ever on peg 3), `sizeTo` becomes 20.U (empty), and the legality check `sizeFrom < sizeTo` passes vacuously, allowing disc update with the invalid peg value. All 40 failing assertions (20 valid_peg + 20 stable_when_illegal) are preserved unchanged as they correctly describe the safety invariant.
