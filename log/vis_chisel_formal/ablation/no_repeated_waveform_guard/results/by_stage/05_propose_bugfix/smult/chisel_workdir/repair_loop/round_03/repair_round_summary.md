Repair round 3: Fixed state_drains_when_inputs_zero assertion error. Root cause: astRelaxedLiveness sets a persistent pending flag that never resets when inputs become non-zero, causing the timer to count cycles where the CSA is accumulating instead of draining. Fix replaced astRelaxedLiveness with a custom drainCounter that only increments during consecutive cycles where inputsZero (i===0 && !j) and state is non-zero (s=/=0 || c=/=0). Counter resets to 0 whenever inputs become non-zero or state drains to zero. Property asserts s===0 && c===0 when drainCounter reaches BITS+1=33. Original assertion label 'state_drains_when_inputs_zero' preserved. No homologous assertions found — this is the only astRelaxedLiveness call in the design.
