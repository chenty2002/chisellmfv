Repair round 2: Fixed state_drains_when_inputs_zero assertion. Root cause: antecedent only checks registered inputs i/j are zero at the current cycle, but since i/j update every cycle, new non-zero inputs can arrive the next cycle and interrupt the drain. Fix: added a RegNext check (inputsStablyZero && prevInputsStablyZero) that requires registered inputs to be zero for two consecutive cycles before the liveness property is asserted. This prevents false triggering when inputs momentarily pass through zero between active multiplications. The drain bound of BITS+1 cycles still provides sufficient margin since the drain effectively starts from the first cycle inputs go to zero. Original assertion label state_drains_when_inputs_zero preserved unchanged.
