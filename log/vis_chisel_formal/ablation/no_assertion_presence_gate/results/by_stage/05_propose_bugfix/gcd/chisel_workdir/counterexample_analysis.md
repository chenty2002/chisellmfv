# Counterexample Analysis Report: `done_clears_busy`

## 1. Verification Environment

- **Top Module**: `Gcd` (8-bit GCD accelerator)
- **Waveform File**: `verilog/extra_bench/gcd/Gcd.done_clears_busy.fst`
- **Source File**: `gcd.scala`
- **Generated Verilog**: `generated/Gcd.sv`
- **Design Description**: A binary GCD computation circuit with a controller (busyReg) and datapath (x, y registers). Inputs `io_a` and `io_b` are loaded when `io_start=1` and `busyReg=0`. The computation runs until `x===y || x===0 || y===0`, at which point `done` fires and the result is captured in `oReg`. The `busyReg` controller sets busy on load and clears it on done.

## 2. Violated Assertion

- **Assertion Name**: `done_clears_busy`
- **Chisel Source** (`gcd.scala`, line 82):
  ```scala
  assertNextStepWhen(done, !busyReg, "done_clears_busy")
  ```
- **Intended Property**: When `done` is asserted, `busyReg` must be deasserted in the **next** clock cycle. In SystemVerilog Assertions (SVA), this should be:
  ```verilog
  assert property (@(posedge clock) disable iff (~hasBeenReset) done |=> !busyReg);
  ```
- **Actually Generated** (`generated/Gcd.sv`, lines 118-119):
  ```verilog
  done_clears_busy:
    assert property (@(posedge clock) disable iff (~hasBeenReset) ~busyReg);
  ```
- **Problem**: The generated assertion is **missing the antecedent** (`done`) and the **next-cycle implication** (`|=>`). It unconditionally checks `~busyReg` at every clock cycle, which is incorrect.

## 3. Waveform Information

- **Waveform File**: `chisel/extra_bench/gcd/verilog/extra_bench/gcd/Gcd.done_clears_busy.fst`
- **Duration**: 2 clock cycles (0 ns to 20 ns)
- **Key Time Points**:

| Time (ns) | Event | busyReg | done | load | io_start | done_clears_busy |
|-----------|-------|---------|------|------|----------|-----------------|
| 0         | Posedge #0 | 0 | 0 | 1 | 1 | 1 (pass) |
| 10        | Posedge #1 | 1 | 1 | 0 | 1 | **0 (FAIL)** |

- **At time 0**: `io_start=1`, `busyReg=0`, so `load=1`. Inputs are `io_a=0xFF`, `io_b=0xFF`. The `done_clears_busy` assertion checks `~busyReg=~0=1` → passes.
- **At time 10** (after first posedge): `x=0xFF`, `y=0xFF` (loaded). Since `x===y`, `done=1`. `busyReg` was set to 1 by the load controller. The assertion checks `~busyReg=~1=0` → **fails**.

## 4. Root Cause Analysis

### Root Cause Category: **Assertion Error** (Incorrect Assertion Generation)

The DUT (Gcd circuit) is **correctly implemented**. The controller logic at `gcd.scala:70-76` properly handles the busy signal:

```scala
// Controller logic
when(!busyReg) {
  when(io.start) {
    busyReg := true.B    // Load: busy goes HIGH next cycle
  }
}.otherwise {
  when(done) {
    busyReg := false.B   // Done: busy goes LOW next cycle
  }
}
```

The correct behavior is observed in the waveform:
- **Cycle 0→1**: `load=1` → `busyReg` becomes 1 (correct — load sets busy)
- **Cycle 1→2**: `done=1` → `busyReg` becomes 0 in the **next** cycle (correct — done clears busy)

### The Bug: `assertNextStepWhen` Generates Incorrect SVA

The Chisel FV library's `assertNextStepWhen(cond, property, name)` function is supposed to generate:
```verilog
assert property (@(posedge clock) disable iff (~hasBeenReset) cond |=> property);
```

However, it actually generates just the property portion without the implication:
```verilog
assert property (@(posedge clock) disable iff (~hasBeenReset) property);
```

**Evidence from generated Verilog (`generated/Gcd.sv`):**

1. **`done_clears_busy`** (line 118-119):
   ```verilog
   done_clears_busy:
     assert property (@(posedge clock) disable iff (~hasBeenReset) ~busyReg);
   ```
   - Missing: `done |=> ` before `~busyReg`

2. **`load_sets_busy`** (line 120):
   ```verilog
   load_sets_busy: assert property (@(posedge clock) disable iff (~hasBeenReset) busyReg);
   ```
   - Missing: `load |=> ` before `busyReg`

**Comparison with correctly generated assertions in the same file:**

3. **`completion_within_200_cycles`** (lines 114-116):
   ```verilog
   completion_within_200_cycles:
     assert property (@(posedge clock) disable iff (~hasBeenReset)
                      ~nextPending | (_nextTimer_T_1 ? _nextTimer_T_2 : 8'h0) < 8'hC9);
   ```
   This uses `~nextPending | ...` which correctly implements `nextPending |-> ...`, generated by `astRelaxedLiveness`. ✓

4. **`output_stable_when_idle`** (line 117):
   ```verilog
   output_stable_when_idle:
     assert property (@(posedge clock) disable iff (~hasBeenReset) busyReg | io_o_0 == r);
   ```
   This uses `busyReg | ...` which correctly implements `!busyReg |-> ...`, generated by `assertStableWhen`. ✓

### Why the Assertion Fails

At time 10 (after the first clock edge):
- `done` = 1 (x === y = 0xFF)
- `busyReg` = 1 (just set by the load from cycle 0)
- The assertion checks `~busyReg` = 0 → assertion fails

The DUT is **correctly operating**: `done` fires at the same cycle `busyReg` is set (since GCD(0xFF, 0xFF) completes in one iteration), and the controller will clear `busyReg` in the **next** cycle (time 20). The assertion should have checked `done |=> !busyReg` which would pass because at time 20, busyReg would be 0.

### Fix Needed

The fix is in the Chisel FV library's `assertNextStepWhen` function implementation. The generated SVA must include the antecedent condition with a next-cycle implication. The correct assertion for `done_clears_busy` should be:

```verilog
assert property (@(posedge clock) disable iff (~hasBeenReset) done |=> !busyReg);
```

Similarly, `load_sets_busy` should be:

```verilog
assert property (@(posedge clock) disable iff (~hasBeenReset) load |=> busyReg);
```

Alternatively, if the Chisel FV library cannot be fixed, the assertions could be manually written using the LTL library directly:

```scala
// Manual fix using LTL directly
import chisel3.ltl._
val doneRose = past(done) === false.B && done === true.B
assert(Sequence.eventually(Sequence.cond(!busyReg))) // etc.
```

However, the proper fix is to correct the `assertNextStepWhen` lowering in the Chisel FV library so that it generates the correct SVA with `cond |=> property`.
