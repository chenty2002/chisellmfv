Fix DUT bug: move interested(self):=true.B from L1 handler to L0 handler (L0→L1 transition). Error: dut_bug. Root cause: the FSM set interested(self) one cycle too late in the L1 handler during L1→L2 transition, but `self` pointer can change between the L0→L1 and L1→L2 steps, leaving processes orphaned at L1 with interested=false. The causal path is: L0 handler decides pc(self):=L1 on non-pause, but interested(self) remains false until the next cycle when pc(self) matches L1 again — if self changes in between, the pc update for that process never occurs, causing the assertion pc(L1) -> interested to fail. Fix: set interested(self):=true.B atomically in the L0 handler's non-paused path, mirroring the L7 handler which clears interested(self) on exit. Remove redundant interested(true) from L1 handler since it's already set on entry. All assertion labels preserved unchanged. This addresses the entering_p0_interested, entering_p1_interested, entering_p2_interested CEXs. The liveness CEXs (stuck processes) are also expected to reduce since processes no longer get orphaned at L1.
