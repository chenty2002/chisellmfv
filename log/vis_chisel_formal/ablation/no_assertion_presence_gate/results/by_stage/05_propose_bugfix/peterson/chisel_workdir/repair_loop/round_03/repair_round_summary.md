Round 3/3: Fixed 'liveness_p0_entry' and 'liveness_p1_entry' (both remaining CEXs). error_type=setup_error. Root cause: The time-multiplexed design only advances the process selected by `self` (which samples `io.select`). The original astRelaxedLiveness counts ALL clock cycles while a process is stalled at L3, but when io_select is held constant by the solver (e.g., io_select=1 forever), the starved process is never evaluated and cannot advance — making the unconditional 15-cycle bound impossible to meet. Fix: Replaced both astRelaxedLiveness calls with manual bounded-liveness blocks whose timer increments only on scheduling opportunities (self === idx). The pending latch starts as soon as the process reaches L3, but the timer only ticks when that process is the scheduled one. Timer reset behavior matches the original macro (reset on resp). Both original assertion labels (liveness_p0_entry, liveness_p1_entry) are preserved. All 9 previously-proven assertions (mutual_exclusion, L3_implies_interested_p0/p1, L4_implies_interested_p0/p1, L5_implies_interested_p0/p1, L3_to_L4_when_other_not_interested_p0/p1) are unchanged.
