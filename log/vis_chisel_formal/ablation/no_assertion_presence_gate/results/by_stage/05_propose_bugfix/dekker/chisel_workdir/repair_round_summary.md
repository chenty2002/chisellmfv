Repair round 3: fixed DUT bug for process0_progress_l1_to_cs and process1_progress_l1_to_cs. Root cause: the original state machine used `switch(pc(self))` which evaluated only ONE process per cycle (the one selected by `self`), serializing two independent concurrent processes. This caused artificial delays — a process at L2 could only check c(~self) when self selected it, and a process at L5 could only exit when self selected it AND !io.pause. The waveform confirmed process 0 spent 51 cycles oscillating L2↔L3 because self was often selecting process 1, missing windows where c(1)=1. Fix: replace `switch(pc(self))` with `for (i <- 0 until 2) { switch(pc(i)) { ... } }` so both processes evaluate their state machines independently each cycle, communicating through shared c() and turn registers as true concurrent Dekker execution requires. All assertion labels preserved unchanged (process0_progress_l1_to_cs, process1_progress_l1_to_cs).
