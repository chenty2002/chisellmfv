Fix DUT bug in ArbitCell.io.xr MUX tree (treearb4.scala:105). The first MUX condition `!holdToken && requesting` lacked the `!io.topCell` guard, causing the root cell (C1_0) to output Phase.request when it had granted the token away but a child was still requesting. Since the root cell has no parent, outputting Phase.request is meaningless and violates the `root_no_request` assertion. Added `&& !io.topCell` to the first condition, making it consistent with the third condition (Phase.release) which already had `!io.topCell`. The root cell now correctly defaults to Phase.idle (or Phase.lock if a descendant holds the lock) when it doesn't hold the token. No homologous assertions exist since this is the only structurally identical Phase.request path in the MUX tree. Assertion label `root_no_request` preserved exactly.
