Round 3/3: Fix reqA_eventually_ackA / reqB_eventually_ackB / reqC_eventually_ackC liveness failures. Error type: dut_bug. Root cause: In Controller IDLE state, the `.otherwise` clause (when not selected) unconditionally cleared `passTokenReg := false.B` (line 88). This destroyed the token whenever the token-holding controller was not the currently selected one by the round-robin arbiter. Since `active = passTokenA || passTokenB || passTokenC`, clearing any passToken caused all three to become zero, freezing the arbiter at Selection.X (deadlock). Fix: removed the `.otherwise { passTokenReg := false.B }` clause entirely. When not selected, passTokenReg now retains its previous value, letting the token persist until intentionally consumed (servicing a request, IDLE+selected+req→READY, line 83) or passed (BUSY+!req→IDLE, line 100). All three controllers share the same Controller class, so the fix applies homologously to all three req*_eventually_ack* assertions. All assertion labels preserved unchanged.
