Round 1/3: Fixed `ackA_implies_reqA` / `ackB_implies_reqB` / `ackC_implies_reqC` assertion failures. Error type: dut_bug. Root cause: Controller BUSY state kept `ackReg` asserted until `!io.req` was detected, but due to register-update semantics, when the client drops `reqReg` on the same clock edge, the controller reads the old `io.req` value (1) and fails to deassert `ackReg` for one extra cycle, creating a window where `io.ack=1` and `io.req=0`. Fix: added unconditional `ackReg := false.B` at the top of the BUSY state (arbiter.scala:94). The ack signal only needs to be high for the single cycle where the client samples it to transition REQ→HAVE_TOKEN (controller sets ackReg in READY, client reads it on the next clock edge). Clearing ackReg immediately in BUSY eliminates the one-cycle stale-ack window. All structurally identical controller instances (controllerA/B/C) share the same Controller class, so all three `ack*_implies_req*` assertions are repaired homologously. Assertion labels preserved unchanged.
