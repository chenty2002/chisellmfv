**Round 1: Fix output_correct_on_done (DUT bug)**. Root cause: when inputs are equal or zero, `done` fires the cycle after `load`, but `oReg` was never updated during the load phase, causing assertion failure because `oReg` still holds 0. Fix: added `oReg := Mux(io.a < io.b, io.a, io.b)` inside the `when(load)` block (line 44 in original, expanded at line 46 in fixed). This ensures oReg holds the correct GCD result when done fires immediately upon the next clock edge. For multi-cycle cases, the `.elsewhen(done)` block still overwrites oReg with the correct value.
