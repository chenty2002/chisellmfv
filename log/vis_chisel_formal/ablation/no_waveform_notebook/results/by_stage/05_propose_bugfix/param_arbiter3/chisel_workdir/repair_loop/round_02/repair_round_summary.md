Round 2: Fix liveness_reqA_ackA failure (DUT bug). Root cause: Controller used a 2-cycle pipeline (IDLE→READY→BUSY) requiring two consecutive cycles of matching selection, but the arbiter changes selection every cycle when active (cycles A→B→C→A). The controller in READY never sees the same selection again and falls back to IDLE, creating livelock — no ack is ever produced. Fix: (1) Change controller to single-cycle pipeline — IDLE→BUSY directly when selected with request, skipping READY. Only one cycle of correct selection needed, matching arbiter behavior. (2) Make ack combinational — io.ack := (state===IDLE) && isSelected && io.req, asserted in the same cycle as the trigger condition, satisfying both liveness_reqA_ackA (immediate ack on trigger cycle, timer never starts) and ackA_implies_sel_A (same-cycle sel=A). (3) In IDLE state, non-selected controllers no longer clear passTokenReg (removed `}.otherwise { passTokenReg := false.B }`), preserving their tokens so active stays high and round-robin arbitration continues fairly. All three liveness assertions (A/B/C) are fixed since they share the same Controller module. All assertion labels preserved unchanged. The ackA_implies_sel_A, ackB_implies_sel_B, ackC_implies_sel_C, mutex_ack, and sel_valid_when_active assertions are also preserved by the single-cycle combinational ack design.
