Round 3: Fix liveness_reqB_ackB and liveness_reqC_ackC failures (DUT bug). Root cause: The Controller BUSY state handler only exits BUSY when io.req drops (condition `!io.req`). When the arbiter cycles back to re-select a BUSY client while io.req is still high, the controller is stuck in BUSY with no exit path — the combinational ack `(state===IDLE) && isSelected && io.req` evaluates to 0 because state is BUSY, so no ack is generated. Fix: In the BUSY state handler, add `.elsewhen(isSelected)` to transition back to IDLE when re-selected while still busy with a pending request. This allows the controller to return to IDLE, and on the next arbiter cycle that selects this client (A→B→C→A rotation), the combinational ack fires within the 10-cycle liveness bound. The fix addresses the causal path: the controller was stuck in BUSY preventing the ack condition from ever re-evaluating as true when re-selected. Both liveness_reqB_ackB and liveness_reqC_ackC are homologous (same Controller module, same liveness pattern) and are fixed together. All assertion labels preserved unchanged.
