Round 3/3: Fixed 2 remaining failing assertions by replacing broken `assertAfterNStepWhen` calls with `fvAssert` using cycle-counter guards. Root cause: generated Verilog reveals `assertAfterNStepWhen(first_cycle, N, cond, label)` drops the trigger (`first_cycle`) and step count (`N`) entirely — e.g. `assertAfterNStepWhen(first_cycle, 1, curr_value===1.U, ...)` generates bare `assert property (@(posedge clock) curr_value == 3'h1)` checked every cycle, causing counterexamples at cycles where curr_value is not 1 (or 0 for the 8-cycle wrap). Fix: add a `cycle_cnt` register (`RegInit(0.U(4.W)); cycle_cnt := cycle_cnt + 1.U`) that counts cycles from reset, then guard each temporal assertion with `Mux(cycle_cnt === N, cond, true.B)` so the check only fires at the correct cycle. Both original assertion labels preserved exactly.
