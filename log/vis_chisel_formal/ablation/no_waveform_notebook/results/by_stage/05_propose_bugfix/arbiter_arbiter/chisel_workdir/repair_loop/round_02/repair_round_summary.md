Round 2/3: Fix Controller IDLE passToken liveness bug (dut_bug). Failing property: Main.reqA_eventually_gets_ack_when_active. Root cause: In Controller class (arbiter.scala ~line 99), the IDLE state `.otherwise` (not selected) branch unconditionally drops passTokenReg to false.B, even when the client has a pending request. This causes all three passTokens to go low, making active=0, which stalls the arbiter (sel=X) and prevents the requesting controller from ever being selected again — a permanent deadlock. Fix: wrap the `passTokenReg := false.B` in `when(io.req) { passTokenReg := true.B } .otherwise { passTokenReg := false.B }` so that a controller with a pending request keeps the system active until the arbiter cycles back to select it. This addresses the causal path (liveness stall through passToken→active→arbiter sel→isSelected), not just the waveform symptom. All six original assertion labels (including the failing reqA_eventually_gets_ack_when_active) are preserved unchanged.
