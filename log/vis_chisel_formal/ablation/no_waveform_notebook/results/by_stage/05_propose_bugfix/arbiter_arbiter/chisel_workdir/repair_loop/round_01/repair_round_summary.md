Round 1/3: Fix Controller READY→BUSY unconditional transition (dut_bug). Failing properties: Main.ackA_implies_reqA, Main.ackB_implies_reqB. Root cause: In Controller class (arbiter.scala:89-92), the is(ControllerState.READY) block unconditionally transitions to BUSY and asserts ackReg, ignoring whether isSelected is still true. This allows a spurious acknowledgment when the arbiter deselects the controller between the READY→BUSY clock edges. Fix: wrap the BUSY transition in when(isSelected) and add an .otherwise branch that resets to IDLE without asserting ackReg. This is a DUT bug fix targeting the Controller FSM shared by all three controller instances (A, B, C). All three original assertion labels (ackA implies reqA, ackB implies reqB, ackC implies reqC) are preserved unchanged.
