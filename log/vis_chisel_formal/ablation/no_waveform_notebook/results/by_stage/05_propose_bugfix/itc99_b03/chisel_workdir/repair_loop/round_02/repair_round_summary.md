Round 2: Fixed DUT bug — fu bits never cleared upon grant issuance in sAssegna state (lines 95-104 of b03.scala). Root cause: when the state machine served a request from the queue head and issued a grant, the corresponding fu (follow-up) bit remained asserted. This had two cascading effects: (1) prevented re-queuing of persistently active requests in the next sAnalisReq cycle because `ruN && !fuN` evaluated false, and (2) created windows where `any_fu=1` and `any_grant=0` (empty queue after shift, stale fu) triggering spurious liveness timer capture for `pending_request_eventually_served`. Fix: added `fu1 := false.B`, `fu2 := false.B`, `fu3 := false.B`, `fu4 := false.B` inside the respective `is(U1)` through `is(U4)` cases of the `switch(coda0)` in sAssegna. This ensures that once a request is served its pending flag is immediately cleared, allowing proper re-enqueuing of sustained inputs and eliminating spurious liveness windows. The fix also addresses the shared root cause of `request_eventually_granted` failures (same stale-fu pipeline stall). Assertion labels preserved unchanged.
